# PDF 근거 열기·하이라이트 연동

## 적용 범위

신규 PDF 업로드 시 페이지별 텍스트와 위치를 함께 추출한다. 페이지 경계를 먼저 나눈 뒤 검색 청크를 만들며, 원문 위치는 `source_documents.pdf_text_locations` JSONB에 저장한다. 위치 데이터에는 원문 문자열을 복제하지 않는다.

마스킹 확정 시 본문과 위치 오프셋을 같은 트랜잭션에서 보정한다. 마스킹된 부분이 포함된 텍스트 영역은 원문 민감정보를 강조하지 않도록 좌표를 제거하고 페이지 정보만 유지한다. 확정 후 임베딩에는 마스킹 본문만 전달한다.

## 응답 계약

채팅 응답·채팅 이력의 `citations[]`에 다음 필드를 추가한다. 준비도 평가와 보완안의 `evidence[]`도 같은 `page`, `quote`, `highlights` 필드를 제공한다. 기존 필드는 유지하며, 준비도 근거의 제목 필드는 기존대로 `fileName`이다.

```json
{
  "sourceId": "자료 UUID",
  "fileId": "파일 UUID (웹/Slack이면 null)",
  "title": "운영 매뉴얼.pdf",
  "type": "FILE",
  "locator": "3페이지",
  "page": 3,
  "quote": "쿠폰 활성 기간과 최소 주문 금액을 먼저 확인하세요.",
  "highlights": [
    { "page": 3, "x": 0.12, "y": 0.35, "width": 0.65, "height": 0.025 }
  ]
}
```

위 예시는 형식 설명용이며 실제 문서에서 추출한 결과가 아니다.

- `page`: **1부터 시작**하는 실제 PDF 페이지 번호. 확인할 수 없으면 `null`.
- 좌표: 기본 회전 0도의 PDF CropBox 왼쪽 위 원점, 너비·높이에 대한 **0~1 비율**. 확대된 표시 크기에 비율을 곱해 그린다. 뷰어에서 사용자가 추가 회전하면 동일한 변환을 적용하거나 하이라이트를 숨긴다.
- `highlights`: 추출 텍스트 영역별 사각형. 문장의 일부를 인용해도 해당 텍스트 영역 전체가 강조될 수 있다. 여러 페이지에 걸친 경우 각 사각형의 `page`로 나눈다.
- `quote`: 현재 안전한 본문에서 확인한 인용문. 채팅은 검색되어 답변 컨텍스트로 전달한 청크의 발췌이며, 모델 답변 문장과 1:1로 연결된 인용 표시까지 구현한 것은 아니다.
- 같은 파일의 여러 청크를 별도 citation으로 유지한다. `sourceId`만으로 카드 key를 만들지 말고 배열 인덱스 또는 위치까지 포함한다.
- 좌표가 없으면 `highlights=[]`; 페이지가 있으면 그 페이지와 인용문을, 페이지도 없으면 인용문과 `locator`를 보여준다. 인용문을 검증하지 못하면 `quote=null`이다.
- 비PDF는 `page=null`, `highlights=[]`이며 문서 본문/청크/채널 등의 `locator`와 인용문을 사용한다. Office의 실제 시트·슬라이드 좌표 추출은 포함하지 않는다.

## 프론트 연결 순서

1. 채팅 citation 또는 준비도 evidence를 클릭하면 `PdfEvidenceDrawer`를 연다. 모바일에서는 전체 화면으로 표시한다.
2. 파일 메타데이터는 기존 `GET /api/v1/handovers/{handoverId}/sources/{sourceId}`로 조회한다. PDF인지 확인한 뒤 기존 `GET /api/v1/handovers/{handoverId}/files/{fileId}/download`를 세션 쿠키와 함께 fetch하여 PDF 뷰어에 바이트/Blob으로 전달한다. 다운로드 API는 기존처럼 attachment이며, 이 응답을 뷰어에서 읽는다.
3. `page`로 이동하고 해당 페이지의 `highlights`를 오버레이한다. 기본 화면 크기가 W×H이면 `left=x*W`, `top=y*H`, `width=width*W`, `height=height*H`이다.
4. 근거 배열로 이전·다음 이동을 구현한다. 비PDF는 인용문·문서 위치를 보여주고 원본 다운로드 또는 외부 링크를 제공한다.
5. 좌표를 다시 조회하려면 아래 API를 사용한다. 이미 응답에 좌표가 있으면 추가 요청은 필요 없다.

`GET /api/v1/handovers/{handoverId}/sources/{sourceId}/evidence?quote={URL 인코딩한 인용문}`

- 인용문 1~4000자, 응답은 위 Citation 형태.
- 공백·줄바꿈 차이를 제외하고 실제 본문과 일치하는지 확인한다. 여러 곳에 반복되어 위치가 모호하거나 일치하지 않으면 위치를 추측하지 않고 `page=null`, `quote=null`, `highlights=[]`를 반환한다.
- 미확정·비활성 자료의 본문은 이 API로 반환하지 않는다.
- 기존 다운로드와 동일한 인계자/인수자/관리자 열람 권한을 검사하며 다른 인수인계의 파일 ID는 404로 처리한다.
- 원본 다운로드는 기존 권한의 원본 PDF를 제공한다. 마스킹된 PDF 바이너리를 새로 만드는 기능은 아니다.

## 배포·기존 자료

- 스키마 변경: `db/migrations/2026-09-19-pdf-evidence.sql`을 적용한다. 자동 DDL을 사용하는 환경에서도 사전 적용 가능하며 반복 실행해도 안전하다.
- **기존 자료·기존 채팅 기록에는 위치 정보가 소급 생성되지 않는다.** 기존 자료는 인용문 중심 보조 화면으로 표시한다. 전체 기능 확인은 새 PDF 업로드 → 마스킹 확정 → 새 채팅/새 준비도 평가로 진행한다. 기존 준비도 평가 캐시는 그대로 유지된다.
- 회전 페이지·세로쓰기 텍스트는 페이지와 인용문만 제공한다. OCR은 추가하지 않았으며 텍스트 없는 스캔 PDF는 기존 추출 실패 흐름으로 처리한다.
- 이 저장소는 백엔드 구현이다. Drawer, PDF 렌더링·오버레이, 모바일 화면은 Baton-FE에서 위 계약으로 구현해야 한다.

## 검증

단위 테스트는 실제 2페이지 PDF 생성·추출, 페이지별 청크, 회전 페이지 보조 응답, 인용문 검증, 마스킹 후 오프셋 보정, 구형 citation 역직렬화, 비참여자·다른 인수인계 원문 접근 차단을 다룬다. 운영 S3/DB 연동과 프론트 실제 렌더링은 별도 통합 검증이 필요하다.
